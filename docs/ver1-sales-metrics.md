상태: **명세 검토 중 / 매출 구현 미착수 / 관리자 대사 미실시**

[제품 계획](product-plan.md)의 지표 제안을 구체화한다. [데이터 계약](ver1-data-contract.md)과 함께 승인해야 하며, 아래 제안 산식을 코드·DTO·DB 기본값으로 확정하지 않는다. 모든 예제는 실제 고객 자료가 아닌 가상의 정수 KRW다.

## 2. 기간과 금액의 의미

- 기간은 KST 시작 시각 이상, 다음 기간 시작 시각 미만의 반개구간을 **제안**한다. 당일·당월 진행 중 보고서는 기준 시각과 데이터 완전성을 표시한다.
- 결제 사건은 결제 시각, 완료된 환불 사건은 환불 완료 시각으로 기간을 판정한다. 주문일·이행일은 별도 축이며 결제일과 혼합하지 않는다. 수집 시각은 사건 귀속일이 아니다.
- 구매 시점의 항목 단가·할인·수량을 사용한다. 현재 카탈로그 가격·공개 표시 가격으로 과거 거래 금액을 재계산하지 않는다.
- 원천의 상품금액이 할인 전인지 후인지 확인한다. 이미 할인이 반영된 결제 상품금액에서 할인을 다시 빼지 않는다.
- 신청·진행 중 환불은 완료 환불에 포함하지 않는 것을 제안한다. 완료를 나타내는 실제 원천 상태 매핑은 승인 대기다.

## 3. 지표 산식 — M03~M11 승인 전 제안

기간 P, 승인된 몰·채널·적격 결제 범위를 전제로 한다. 결제 시점에 집계된 항목과 이후 환불 사건을 분리한다.

| 지표 | 산식·포함 기준 | 미해결 조건 |
|---|---|---|
| 총상품매출 G(P) | P 내 적격 결제 항목의 `구매 수량 × 구매 당시 할인 전 단가` 합 | 단가·적격 상태·재결제 정의 |
| 할인액 D(P) | 위 결제 항목의 항목 할인 + 배분된 주문 할인 | 중복 없는 배분·쿠폰·적립금 정책 |
| 결제 상품금액 B(P) | `G(P) − D(P)`; 원천의 할인 후 상품금액과 대사 | 세금·적립금 정책을 맞춘 뒤 사용 |
| 상품 환불액 R(P) | P 내 완료된 환불 사건의 할인 후 상품 대가 환불 합 | 배송비 분리·현금/적립금 구성·중복 방지 |
| 순상품매출 N(P) | `B(P) − R(P)` | 결제일 기준 채택과 구성 금액 승인 |
| 배송비 S(P) | P 내 결제 배송비(승인된 배송 할인 반영) − P 내 완료 배송비 환불 | 상품매출 제외, 배송 할인·세금 정책 |
| 결제 주문 수 O(P) | P 내 적격 결제 주문의 고유 주문 ID 수 | 분할/재결제·전체 취소 제외 기준 승인 |
| 순판매 수량 U(P) | P 내 적격 결제 수량 − P 내 완료된 수량 환불/취소 조정 | 취소·환불 이중 차감 금지, 금액만 환불 시 수량 정책 |
| AOV | 아래 두 후보를 비교 후 하나를 명시적으로 승인 | 아직 산식 확정 안 됨 |
| 상품 순위 | 상품별 순판매 수량, 순상품매출, 고유 구매 고객 수를 각각 순위화 | 항목 환불 배분·비회원 고객 식별·동점 기준 승인 |

상품만 환불된 경우 배송비는 차감하지 않는다. 미결제 취소는 결제 매출에 처음부터 포함하지 않는 것을 제안한다. 이미 결제된 주문의 취소와 환불이 같은 사건이면 한 번만 조정한다. 원천 관계를 확인하기 전 임의로 둘을 합치거나 각각 차감하지 않는다.

금액 환불에 수량이 없으면 단가로 나눠 수량을 추정하지 않는다. 환불만 있는 기간은 순매출·순수량이 음수일 수 있으며 0으로 절삭하지 않는다. 고객 누적 구매액·휴면/충성 기준·인구통계는 이번 명세에서 확정하지 않는다.

### AOV 후보와 왜곡

- 후보 A: `N(P) / O(P)`. 기간 손익 흐름과 당기 주문 수가 섞이므로 과거 주문 환불로 값이 낮거나 음수가 될 수 있다. 분모 0이면 정의 불가로 표시한다.
- 후보 B: P 내 결제한 주문 코호트의 할인 후 상품금액에서 **그 주문들에 연결된 기준 시각까지의 환불**을 차감한 금액 / 승인된 코호트 주문 수. 기준 시각·전체 취소 주문 제외 기준을 표시한다. 과거 코호트 AOV는 환불 도착에 따라 변할 수 있다.

후보 B의 변화는 환불을 원결제일 매출에 재귀속하는 것이 아니라 별도의 주문 코호트 지표다. 제품 계획의 전체 취소 주문 제외 제안도 분자·분모에 일관되게 적용할 기준 승인이 필요하다. AOV를 승인 전 대표 지표로 구현하지 않는다.

## 4. 수치 예제

### 월 경계 부분 환불

적립금·추가 할인·수수료가 없고 상품금액의 세금 기준이 일치한다고 **예제에 한해서** 가정한다. 10월 적격 결제 주문 1건: 할인 전 상품금액 100,000원, 할인 10,000원, 배송비 3,000원, 총 결제액 93,000원. 11월에 할인 후 상품 대가 20,000원 환불이 완료되고 배송비 환불은 없다.

| 항목 | 10월 | 11월(신규 결제 없음) |
|---|---:|---:|
| 총상품매출 G | 100,000 | 0 |
| 할인액 D | 10,000 | 0 |
| 결제 상품금액 B | 90,000 | 0 |
| 완료 상품 환불액 R | 0 | 20,000 |
| 순상품매출 N | 90,000 | −20,000 |
| 별도 배송비 S | 3,000 | 0 |
| 결제 주문 수(예제 후보 기준) | 1 | 0 |

10월 순상품매출은 환불 때문에 70,000원으로 바뀌지 않는다. 11월에 90,000원의 신규 상품 결제 1건이 추가되면 후보 A의 AOV는 `(90,000 − 20,000) / 1 = 70,000원`이지만, 신규 주문 자체의 상품금액은 90,000원이다. 신규 결제가 없는 표의 11월 AOV는 분모가 0이므로 0원이 아니라 정의 불가다.

### 정상·할인·전체 환불

- 수량 2 × 단가 50,000원, 할인 없음: 총상품매출과 결제 상품금액은 각각 100,000원이다.
- 같은 거래에 항목 할인 6,000원, 배분된 주문 할인 4,000원: 할인액 10,000원, 결제 상품금액 90,000원이다. 원천이 90,000원을 이미 제공하면 여기에서 다시 할인하지 않는다.
- 위 할인 거래의 상품 대가 전액 90,000원이 다음 달 환불 완료되면 다음 달 상품 환불액은 90,000원이다. 최초 할인 전 100,000원을 환불액으로 가정하지 않는다. 앞선 부분 환불 20,000원이 있었다면 추가 잔여 환불 70,000원인지 누적 90,000원인지 원천 의미를 확인해 중복을 방지한다.

## 5. 검증과 관리자 대사

문서 예제 검토와 실제 관리자 대사는 구분한다. 현재 실제 API·데이터·관리자 화면을 조회하지 않았으며 대사를 통과했다고 주장하지 않는다.

| 시나리오 | 확인할 결과 |
|---|---|
| 정상 결제·할인 | 구매 스냅샷으로 계산, 할인 중복 차감 없음 |
| 부분·전체·월 경계 환불 | 완료일에 실제 상품 환불액을 한 번 반영, 원결제일 유지 |
| 취소와 환불이 함께 제공됨 | 같은 경제 사건 이중 차감 없음; 매핑 미승인 시 보류 |
| 중복 가져오기·지연 도착 | 합계 중복 없음, 완료일 기간 반영과 재집계 시각 표시 |
| 결제·환불 시각/상품 연결 누락 | 격리·영향 지표 표시, 추정값·정상 0으로 대체 안 함 |
| KST 자정 경계 | 2026-10-31 14:59:59Z는 10월, 15:00:00Z는 11월에 한 번만 포함 |
| 현재 상품 가격 변경 | 기존 주문의 단가·할인·매출 불변 |
| 환불만 있는 기간·AOV 분모 0 | 음수 매출 보존, AOV 정의 불가 표시 |
| 미연동·불완전 기간 | “데이터 연동 대기” 또는 “데이터 불완전”, 누락 범위·마지막 동기화 표시 |

실제 0은 승인된 범위의 데이터가 완전하고 대사가 완료된 무거래 기간에만 표시한다. 부분 데이터는 전체 매출처럼 제시하지 않는다.

관리자 대사 기록에는 다음을 남긴다.

1. 승인된 원천·몰·채널·기간·상태·결제/환불 귀속 기준 및 지표 계약 버전.
2. 비교 화면/보고서 이름·필터·추출 시각·데이터 기준 시각과 가져오기 배치 참조. 고객 원본·비밀 값은 첨부하지 않는다.
3. 동일 기준의 총상품매출·할인·상품 환불·배송비·순상품매출·주문 수 합계, 시스템 값·원천 값·차이와 원인.
4. 선택한 정상일·할인일·부분/전체 환불일·월 경계·월 합계 결과. 환불 귀속 방식이 다른 원천 보고서는 차이를 설명하고 동일 기준 비교 가능 여부를 확인한다.
5. 승인 담당자·검토일·허용 오차·미해결 차이·재검증 결과. 허용 오차는 현재 미정이며 차이를 임의로 허용하지 않는다.

## 6. 구현 착수와 변경 관리

접근 승인 체크리스트, 실제 원천 매핑, 구현 대상 지표의 미결정 정책이 승인된 뒤 해당 범위 구현을 시작한다. 한 지표 승인으로 다른 미정 지표까지 구현하지 않는다. 원천 오류 정정·정책 변경은 영향 기간과 계약 버전을 기록하고 별도 승인하며, 환불과 원천 오류 정정을 혼동하지 않는다.

이번 변경에는 API·DTO·DB·실제 데이터 접근·발송·커밋이 없다. 요청·검증·출시 상태는 [Ver.1 요청 기록](CHANGE_REQUEST_TEMPLATE.md#ver1-요청-기록--명세-검토-단계)과 [변경 기록](../CHANGELOG.md)에 남긴다.
