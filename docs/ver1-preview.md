# Ver.1 Streamlit 초안과 실제 데이터 연동 방향

요청일: 2026-10-20 (Asia/Seoul). 상태: 로컬 검토용 초안, 운영 출시 아님.

## 지금 확인할 화면

기존 문서 명세 단계 이후 요청자가 화면 구현을 요청했고, 상품명·가격은 공식몰 자료를 사용하도록 수정 요청했다. 이번 구현은 그 후속 요청이며, 앞선 문서 전용 작업 기록은 당시 범위로 보존한다.

- 사장님 요약: 기간 매출 추이·환불·주문·구매 고객 요약.
- 매출·상품: 공식몰 상품 검색·분류·가격·출처, 판매 상위/하위·순매출 순위, 구매 목록.
- 리뷰: 리뷰 수·평점 순위. 무리뷰 상품을 평점 0으로 처리하지 않고 평점 순위에서 제외.
- 고객 동향: 첫 구매·이전 구매·기간 내 반복 구매; 프로필·로그인 연동 상태.
- AI 마케팅 제안: 집계 수치·근거·권장 행동·효과 확인 방법. 현재는 규칙 기반이며 Gemini 생성이 아님.
- 연동·운영: 실제 수집→Supabase 저장→집계→요약→AI 제안 연결 상태.

기본 모드 **공식몰 상품 · 실적 연동 대기**는 실제 공개 상품 카탈로그만 보여준다. 주문·고객·환불·리뷰 실적을 0으로 가장하지 않는다. **가상 실적 화면 미리보기**는 UI 검토용 거래·환불·리뷰·고객 시나리오를 제공하며 실적이 아님을 표시한다. 가상 거래 금액은 공개 가격과 독립적이며 실제 과거 구매가로 사용하지 않는다. 기타 매출과 AOV는 정의 승인 대기로 남긴다.

후속 요청으로 데모 로그인 게이트를 추가했다. `user@example.com`과 비어 있지 않은 임의 비밀번호로 로그인하면 기존 분석 화면이 열리고, 로그아웃하면 로그인 화면으로 돌아간다. 비밀번호는 외부 전송·저장하지 않는다. 이 기능은 Streamlit 로컬 세션의 화면 전환이며 Supabase Auth·JWT·역할·API 권한 검사를 대체하지 않는다.

## 공식몰 카탈로그 수집 결과와 재수집

후속 요청으로 화면의 상품 분류와 필터는 제거하고 [영문 엑셀 용량·EAN 연결](ver1-product-specifications.md)을 추가했다. 아래 분류 수집 설명은 원천 관측·수집 범위 검증에 관한 기록이며 현재 화면의 필터 기능을 뜻하지 않는다. 기존 가격 관측은 유지한다.

- 출처: https://ecladomall.co.kr/ 및 연결된 공개 상품 분류 목록. 2026-10-20 수집.
- 70개 공개 페이지에서 고유 상품 ID 116개 확인. 유형별 목록의 표시 전체 116개와 수집 고유 ID 116개 대사 일치. 판매가 미확인 상품 0개.
- 공개 홈·유형별·고민별·라인별·프로모션에서 연결된 분류와 페이지네이션을 순회했다. 비공개·삭제·미노출 상품, 옵션별 추가금·회원별 결제 가격·개인화 혜택은 전체 수집을 보장하지 않는다.
- 상품명·상품 ID·분류·상품 URL·이미지 URL·판매가·할인판매가·소비자가·관측 URL·관측 시각을 보존한다. 금액이 없는 경우 임의 금액을 만들지 않는다.
- 목록별 가격이 다르면 표시하고 원래 관측들을 보존한다. 화면 대표값은 최초 발견 목록(유형별 우선)의 관측이며 가장 낮은 가격을 임의 채택하지 않는다. 기간 필터는 거래·리뷰 시나리오에 적용되며 가격 관측을 과거 가격으로 바꾸지 않는다.
- `backend/eclado_backend/stores/data/public_catalog.json`은 현재 화면용 스냅샷이고 `catalog-<UTC시각>.json`은 보존 관측이다. HTML·쿠키·로그인 데이터는 포함하지 않는다. Supabase 자동 저장은 아직 아니다.
- 수집은 robots.txt를 확인하고 공개 홈·상품 목록만 순차 조회한다. 로그인·내부 API·보호 페이지·리뷰 원문은 수집하지 않는다. 오류·건수 불일치·페이지 상한은 불완전 상태로 기록한다.

명시적 재수집(화면 진입/새로고침마다 네트워크 수집하지 않음):

```powershell
uv run python tools/refresh_public_catalog.py
```

오류가 있으면 스냅샷 `errors`, `complete`, `declared_counts`, `collected_counts`, `visited_urls`를 검토한다. 재수집 시 판매·리뷰 실적을 공개 상품 가격으로 생성하지 않는다.

## 향후 실제 사건과 Supabase 자동 저장

요청한 최종 방향은 **실제 들어오는 데이터 → Supabase → 사장님 요약 → 근거가 있는 AI 마케팅 제안**이다. 아래는 후속 구현 요구사항이며 현재 연결 완료를 의미하지 않는다.

| 데이터 | 승인 후 수집·저장할 내용 | 확인 필요 |
|---|---|---|
| 고객 가입·로그인·계정 변경 | 제공되는 고객 원천 ID·사건 ID·발생 시각·최소 프로필 변경 | 쇼핑몰이 제공하는 사건/API, 소급 이력, 접근 승인 |
| 이름·전화번호·성별·나이 | 승인된 직접 제공 정보, 목적·증빙·수정/삭제 이력; 분석에는 나이대 등 최소화 | 필드 실제 제공 여부·수집 목적·역할·보관 기간; 미제공을 추론하지 않음 |
| 구매·결제·항목 | 구매 시점 단가·할인·수량·배송비·결제 상태·원천 ID | 승인된 주문 API/공식 내보내기, 상태·금액 매핑 |
| 취소·환불 | 원거래 연결·부분/전체 사건·완료 시각·상품/배송비 구성 | 중복 차감 방지·재결제·환불 구성 정책 |
| 리뷰 | 제품 연결·원천 ID·작성 시각·평점, 승인된 최소 내용 | 공식 제공 경로·원문 보관 필요 여부·구매 연결 |
| 매출·기타 매출 | 원장 기반 상품/할인/환불/배송비 분리 집계·별도 매출 원천 | 기타 매출의 사업 정의와 원천, 지표별 승인 |

쇼핑몰 로그인·주문과 Supabase 직원 Auth는 자동으로 동일하지 않다. 로그인만으로 성별·이름·전화번호·나이·구매가 모두 확보된다고 가정하지 않는다. 구매 고객의 원천 ID와 내부 고객 ID를 연결하고, 직원 인증은 별도의 역할 모델로 관리한다.

승인된 API/공식 내보내기와 제공되는 웹훅을 검토해 수집 작업을 구현한다. 웹훅 사용 시 서명·재전송·중복 검증, 주기 동기화 사용 시 수정 커서·겹침 조회·누락 재대사, 공통으로 원천 사건 ID·배치·격리·재시도·감사 이력을 갖춘다. 웹훅의 실제 제공 여부·실행 주기·지연 SLA는 현재 미정이다. 도착이 늦어도 환불은 완료일에 귀속한다.

Supabase 저장 전 직원 인증·서버 역할 검사·RLS·최소 수집·보관/삭제·환경 승인을 완료하고, 고객 원장과 집계를 분리한다. service role 키는 서버에만 둔다. 미결정 정책은 [데이터 계약](ver1-data-contract.md)과 [매출 명세](ver1-sales-metrics.md)의 승인표에서 확정한다. 기존 SQL 초안은 이번에 적용하지 않았다.

Gemini에는 승인된 집계·최소화된 근거만 공급하고 모델·프롬프트 버전·분석 기간·표본 수·검토 상태를 기록한다. 이름·전화번호·원본 개인정보를 추천 입력으로 기본 전송하지 않는다. 제안은 사장님이 검토하며 자동 메시지는 별도 동의·억제·빈도·멱등성·감사 검토 전 비활성이다.

## 검증·복구

API는 `/api/v1/dashboard/preview?source=pending|demo&start=YYYY-MM-DD&end=YYYY-MM-DD`를 제공한다. 기본은 pending이며 로컬 공개 카탈로그와 선택적 가상 실적만 반환한다. 실제 데이터 업로드·수집 HTTP API는 없다.

서비스는 매출·환불 귀속·상품/일 합계·고객 집계를 담당하고 store와 추천 인터페이스를 사용한다. Streamlit은 dashboard repository와 shared transport·DTO를 통해서만 백엔드를 호출한다. 외부 네트워크가 없는 parser/client fake 테스트와 Streamlit AppTest를 사용한다.

검증 명령은 `uv run pytest`, `uv run ruff check .`, `uv run mypy`. 이번 환경에서는 전역 uv 캐시 접근 제한으로 `uv --cache-dir .cache/uv run --offline --no-sync <명령>`을 사용한다. 실행 결과는 요청 기록에 남긴다.

복구 시 로컬 서버를 중지하고 dashboard preview 라우터 등록·새 UI·preview 모듈과 문서 변경을 이전 상태로 복원한다. 공개 스냅샷은 보존하고 잘못된 수집은 이전 스냅샷을 최신 포인터로 복원한다. DB 변경·데이터 마이그레이션·운영 배포·커밋은 없다.
